# Sirnaaz by Mehar — online store

React + TypeScript + Vite + Tailwind storefront, a Hono API running as one **Netlify Function**,
**Supabase** PostgreSQL for data and **Supabase Storage** for product photos. Everything fits free tiers.
**To go live, follow [SETUP.md](SETUP.md).**

```
Browser ──▶ Netlify (website files) ──/api/*──▶ Netlify Function (server/app.ts) ──▶ Supabase PostgreSQL
   │                                                    │ issues one-time upload links
   └──── photos (resized in the browser) ──signed PUT──▶ Supabase Storage (public read)
```

## Security model

- **The browser never talks to the database** and holds no keys. Every price, discount, total, stock check,
  coupon and admin permission is decided in the function.
- **Supabase's own public API is locked:** Row Level Security is on for every table with no policies, and the
  `anon`/`authenticated` roles have no table privileges. Check any time with `npm run db:check`.
  Any new table added in a future migration must `ENABLE ROW LEVEL SECURITY`.
- **Admin:** separate `admin_users` table and separate session cookie; every `/api/admin/*` request is checked on
  the server. The first admin is created once through `/admin` with `ADMIN_SETUP_TOKEN`; the screen then closes.
- **Sessions:** random 256-bit token in an httpOnly cookie (`__Host-`, Secure, SameSite=Lax over HTTPS); only its
  SHA-256 is stored; logout deletes it; customers 30 days, admins 12 hours.
- **Passwords:** scrypt (N=2^17, r=8, p=1), built into Node.
- **Rate limits:** stored in Postgres (`rate_limits`), so they hold across all function instances.
- **Orders:** stock rows are locked per size and decremented conditionally in one transaction; an
  `Idempotency-Key` makes double-clicks, retries and lost responses return the same order.
- **Photos:** only admins can get upload links; the bucket accepts only JPEG/PNG/WebP ≤ 10 MB; the server checks the
  real file bytes before recording a photo and deletes anything that isn't an image.
- **Headers:** strict Content-Security-Policy naming your Supabase project (generated at build into `dist/_headers`),
  HSTS, `Referrer-Policy: same-origin`, no framing.

## Project layout

| Path | What's there |
|---|---|
| `netlify.toml`, `netlify/functions/api.mts` | Netlify build + the function that runs the API at `/api/*` |
| `server/app.ts`, `server/routes/` | The API (public, auth, account, admin) |
| `server/lib/` | Sessions & hashing, rate limits, storage, orders, settings, email |
| `server/db/migrations/` | Schema; applied once via `supabase/setup.sql` (never at runtime) |
| `supabase/setup.sql`, `sample-products.sql` | Generated by `npm run db:build-sql`; paste into Supabase SQL Editor |
| `src/` | The storefront, account and admin screens |
| `src/lib/imageProcess.ts` | Browser-side photo preparation (rotation, resize, WebP/JPEG, thumbnail) |
| `scripts/write-headers.mjs` | Writes security headers at build time |
| `scripts/dev/mock-supabase-storage.mjs` | Local stand-in for Supabase Storage (testing only) |

## Commands

```bash
npm run dev            # netlify dev: website + API function on http://localhost:8888
npm run build          # production build (Netlify runs this)
npm run db:build-sql   # regenerate supabase/setup.sql after changing migrations or seed data
npm run db:migrate     # apply new migrations to DATABASE_URL (for later schema changes)
npm run db:check       # verify Row Level Security and locked public roles
npm run create-admin   # create/reset an admin from your computer (see SETUP.md)
```
